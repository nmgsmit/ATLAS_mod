### Tips

Core mechanism: annotate objects at one or more frames and use propagation to complete the video.
Use permanent memory to store accurate segmentation (commit good frames to it) for best results.
The first frame to enter the memory bank is always committed to the permanent memory.
Reset memory if needed.

Controls:
- Open... (the button in the "Clip" group, or O) loads another clip without restarting: pick a raw video from the Raw videos tab or an existing workspace from the Workspaces tab. Videos already imported are tagged "in workspace" (green) with their frame count -- opening one of those continues that annotation rather than re-extracting frames; a "not imported" video has its frames extracted into a new workspace on open, using the video's raw_videos subfolder in the workspace name so clips from different folders do not collide. Type in the filter box to narrow the list. Stop any propagation before switching.
- Use middle-click inside the image window to toggle between click-based segmentation and polygon-based segmentation.
- For click segmentation, use left-click for foreground annotation and right-click for background annotation.
- For polygon segmentation, use left-click to add points, and right-click to undo the last point. Note that a point placed within ~8 px of the first point closes the polygon, so very small shapes cannot be drawn -- zoom in or use click segmentation for those.
- ERASER (the button in the "Edit" group, or E) makes a finalized polygon return its interior to background instead of painting the current object: draw around a stray mask and it is gone. The outline turns red while the eraser is armed. It clears every label inside the polygon, not just the current object, so enclose only what you want removed. This rewrites the current frame's saved mask only -- the memory bank is not touched, so there is no need to reset memory to remove a blob. Leaving polygon mode disarms the eraser.
- Use Ctrl+Z to undo the last click interaction or the last polygon point. With no points half-drawn it undoes the last finalized polygon (paint or erase) on that frame -- one level, and only while you stay on the frame.
- An erase only fixes the frame you erased on. If the blob came from propagation it still lives in the memory bank: after cutting, commit the corrected frame (C) and propagate again, otherwise the next pass paints it straight back. If it keeps returning, the bad mask is in permanent memory and needs a memory reset.
- Change the object being painted from the "Class" box: click a coloured class button, press its number key (1–6), or cycle with [ (previous) and ] (next). The "Painting:" line at the top of that box always shows the active class and its colour. If a class is missing, the correct number of objects was not specified during program startup.
- Mode -> "Arch annotation" overlays a parabolic arc for the arch of the cave of Retzius, stored per frame: left-click the two sides of the cave, then the tip on the urethra. The tip always stays on the mid-line between the sides; drag it (even past the image border) to set the arch height, and drag the side handles to calibrate them with the cave walls. Once a frame's arch is set it cannot be removed, only its points can be dragged. Right-click undoes an in-progress placement click; middle-click (or Mode -> "Mask annotation") leaves edit mode. Arcs persist across restarts (workspace/arches.json).
- TRACK ◀ / TRACK ▶ carry the arch backward/forward from the current frame: place it on a clear frame -- typically near the end of the video, then TRACK ◀ -- and probe points on the tissue carry the (always perfect) parabola through the other frames. This is the arch's own pass: it only follows points, so it is fast and it never rewrites your masks. Each probe is trusted by how well it still matches, how well it agrees with the other probes, and whether an instrument is covering it, so one probe sliding onto an instrument cannot drag the arch. A cyan arc is trusted, amber means the probes disagreed there (worth a nudge), gray means tracking lost its grip and that frame is holding the previous shape. Every frame you adjust by hand becomes a keyframe that a later run snaps back to: correct a frame, then TRACK again from there. Either TRACK button pauses a run in progress; the one that is running stays lit while it goes, while it runs.
- The "Arch tip" slider sets the arch height directly -- drag it or scroll on it. Use this when the tip sits outside the image and there is no handle to grab: the tip stays on the mid-line and the parabola stays exact. It runs 0-500 px above the base chord. It mirrors the tip handle both ways, and counts as a hand-correction (making that frame a keyframe) just like dragging.
- The "Sharpness" slider is the arch's shape: the two sides and the tip pin where the arc starts, ends and peaks, but not how sharply it turns over in between. 2.0 is the plain parabola, lower pinches the tip to a point, higher flattens the crown and steepens the arms (range 1.5-3.0). Like the tip slider it makes that frame a keyframe, and TRACK carries the shape along.
- RESET ARCH is the way out if an arch is misplaced or a propagation run went wrong: it asks whether to clear just the current frame or every frame, and Cancel is the default. This is the only way to remove an arch (a stray click can't), and it cannot be undone.
- The arch can see robot instruments if you annotate them: segment the instruments as the "Non-anatomical" object and propagate them like any other object first -- TRACK then reads those saved masks, so it knows which probes are blind and ignores them instead of guessing (it does not see through an instrument; the remaining probes and the parabola carry the arch across). Entirely optional: with no instrument masks TRACK behaves exactly as before. If instruments cover too much of the arch to track at all, TRACK says so rather than guessing.
- Mode -> "Scale annotation" holds the three references of known physical length, stored per frame: the ruler (1 cm by default), the catheter tip (16/3 mm) and the robot arm (8 mm across). Pick which one you are working on exactly like a segmentation class -- click a coloured button in the "Reference" box, press its number key (1-3), or cycle with [ and ]. The ruler and the catheter tip are DRAWN: left-click their two ends, and that is all there is to it, since they are always a straight line (no tip and no sharpness, unlike the arch). Drag the end handles to correct. Right-click (or Ctrl+Z) undoes an in-progress placement click; middle-click leaves the mode. One of each reference per frame; everything persists to workspace/scale_objects.json, which records each object's real mm, its endpoints, its tracking points and the mm/px they imply -- ready to be read by a depth-estimation loss. The robot arm is different -- see the next three tips.
- "Open..." (the button, or `O`) browses more than one folder of source videos: the project's own `raw-videos`, and `../data` next to the checkout. Folders that do not exist are simply skipped, and the list is set by `raw_videos_root` and `extra_video_roots` in `gui/cutie/config/gui_config.yaml` -- add a line there to browse somewhere else. Each group in the list is labelled with the folder it came from, so you can see which root a clip is in; with this many folders they start collapsed, and the filter box searches across all of them at once. A video's workspace is named after its path under whichever root holds it, so the many `clip_001.mp4` in different case folders each get their own workspace instead of colliding. Note that the same recording copied into two roots counts as two videos and gets two workspaces -- they are different files as far as the tool is concerned.
- Black bars are cut off automatically when a video is first opened. Endoscope recordings are letterboxed -- the console writes a squarer feed into a 16:9 file and pads the sides -- and that padding is not picture: it wastes a fifth of the segmentation networks' input resolution, and an instrument running off the side of the picture never reaches the edge of the FILE, which is where the robot-arm tool anchors its centerline. The bars are detected once from frames sampled across the clip and the same box is used for every frame, so nothing moves; the box is recorded in workspace/source_crop.json, so a pixel coordinate in the workspace can always be mapped back to the original video. Typical result on this data: 1920x1080 becomes 1344x1074. A workspace extracted BEFORE this existed keeps its bars -- the console says so when you open it. To re-extract, delete that workspace's `images` folder and open the video again; any masks or annotations already drawn on those frames are in the old coordinates and will not line up, so only do it on a workspace you have not annotated yet.
- The robot arm is MEASURED, not drawn, and it is FOUR POINTS: the two where the arm enters the picture (one per side) and the two at the end of its straight shaft -- the wrist, NOT the tip of the tool. Its 8 mm is its diameter, and a diameter only means anything taken square to the shaft, which is what those four points give: the centerline runs between the two midpoints and the white scale line is the width across, square to it. Segment the arm as the "Non-anatomical" object and propagate it like any other object first (the same masks the arch uses as occluders). Then pick reference 3 and left-click the arm once to say WHICH instrument it is -- the four points are guessed off that mask. If nothing appears, there is no instrument mask reaching the image border on that frame: this tool measures the mask, it does not find the arm.
- MEASURE CLIP guesses the four points off every frame's mask and then reconciles the frames against each other, and the reconciliation is the part worth knowing about: each frame exports the local median of its neighbours, and a frame that disagrees with its neighbours is dropped. The reason is that a single frame cannot see its own error. Segmentation error is common-mode -- a mask a pixel too fat pushes BOTH sides of the arm outward, so the width stays perfectly consistent and perfectly wrong, and every check the frame can run on itself still says fine. What does see it is the neighbouring frames, where a rigid arm has barely changed width. Frames whose points you placed by hand are never redone.
- CALIB is the one knob reconciliation cannot replace. Smoothing removes jitter; it cannot remove a mask that is fat on EVERY frame, which reads wide on every frame. So the readout compares the arm against your hand-drawn RULER on frames that have both -- the ruler is drawn on something visible and carries none of the mask's bias -- and tells you the ratio. Apply it in Calib only if the ruler and the arm are at a similar depth: mm/px is a property of a point in the picture, not of the picture, so a ruler lying on tissue further away genuinely reads different and "correcting" to match it would scale away a real depth difference.
- Per frame there are two things to do. Drag any of the FOUR SQUARES that landed in the wrong place -- the guess misses when the arm blends into another instrument at the border, or when the wrist fooled the walk down the shaft -- and watch the reading settle as you drag. A frame you touch becomes a keyframe: TRACK re-seeds there and MEASURE CLIP leaves it alone. And D (or right-click) drops a frame you do not believe; your answer is final, and no later re-measure overrides it.
- The "Length" box is the real size of the active reference. Only the ruler's is editable (you choose how much of the ruler to span, 10 mm by default) -- the catheter tip and the robot arm are fixed instrument properties, so the box goes read-only for those. Changing the ruler's length applies to every frame it is drawn on, since it is one physical span. The line under it reads back the current frame: pixel length, mm, and the resulting mm/px.
- Each reference carries 5 tracking points spread along it. Normally they are derived from the two ends and cannot be grabbed, so a stray click can never nudge one. Tick "Edit tracking points" to make the interior ones draggable -- useful when one sits on a specular highlight or an instrument edge. A dragged point slides ALONG the line (it is projected back onto it), so the reference always stays straight and only the tracking spot moves. The tickbox is off by default and does not persist any state of its own.
- TRACK ◀ / TRACK ▶ in the "Reference tracking" group carry every reference drawn on the current frame through the video, in its own pass -- it follows the tracking points only, so it is fast and it never rewrites your masks. It uses the same trust model as the arch: appearance, agreement between the points, and the instrument masks ("Non-anatomical") if you annotated them. Class colour = trusted, amber = the points disagreed there, gray = lost grip and holding the last pose. Any frame you correct by hand becomes a keyframe a later run snaps back to. F/space and B do the same from the keyboard while the mode is active; either TRACK button pauses a run.
- The robot arm rides along a TRACK pass with its own tracker: the four points are carried from the frame you start on, so correct them THERE first. A point the tracker loses is moved by however far the others went (the arm is rigid), and the entry pair is kept on the image border where it belongs. A frame you corrected by hand is a keyframe and is never overwritten -- the tracker re-seeds on it instead, so a correction propagates from where you made it. MEASURE CLIP is the other way in: it re-guesses every frame off its own mask rather than carrying anything, which is better when the arm's mask is good and worse when the wrist keeps fooling the walk.
- RESET REFERENCE clears the ACTIVE reference only (the other two are untouched), asking whether to clear just this frame or every frame. It is the only way to remove a drawn reference, and it cannot be undone. For the robot arm, clearing every frame also forgets which instrument you pointed it at.
- Use left/right arrows to move between frames, shift+arrow to move by 10 frames, and alt/option+arrow to move to the start/end.
- The Speed selector (0.5×–8×) in the "Frame" group sets the pace of Play video, Propagate and Track. For Play it skips through frames faster; for Propagate/Track every frame is still processed and saved, it just redraws the preview less often so the run finishes sooner (handy for arch tracking, which needs little watching). It never changes how many frames are annotated, and you can change it mid-run.
- Use F/space and B to run forward and backward. These follow the Mode: in Mask annotation they propagate the segmentation (the "Segment" group); in Arch annotation they run arch tracking; in Scale annotation they run reference tracking (each mode's run group sits in the same place). So while tracking, space controls that TRACK run and never triggers segmentation propagation. Press the same key again to pause.
- Use T to toggle between visualization modes.
- Use C to commit a frame to permanent memory.
- Memory can be corrupted by bad segmentations. Make good use of "reset memory" and do not commit bad segmentations.
